# 找岗结果整理优化

2026-10-23。根据用户要求，将链接列表改为统一招聘卡片，允许粗略预测难度。沿用既有 Vue/FastAPI/PostgreSQL、持久 Worker 与 Tavily/DeepSeek。

## 使用

刷新 http://localhost:8081/discover，输入“帮我找找杭州开发相关实习”，点击“AI 找岗位”。默认最多3组查询，每组最多8条来源，去重后分批整理；高级设置可指定城市、每周天数和查询组数，刷新可恢复。

卡片展示公司、岗位、地点、薪资、学历、职责、要求、原始来源与 AI 预测难度/准备建议。可看推荐/全部，按难度筛选与排序。同公司/岗位/地点合并来源；保存申请意向只建立 interested 档案，不执行实际投递。

旧结果点击“AI 整理已有链接”或“重新整理结果”，仅分析已保存材料，不重新执行 Search/Extract。每次整理保存新版本，同一幂等请求不会重复建版本或覆盖完成结果。

找岗页的公开信息授权只覆盖搜索条件和公开资料，不读取简历、不修改全局个人资料模型授权。个人简历、材料和题单仍走原授权检查。

## 信息与实现边界

事实字段必须能从对应来源中直接截取，缺失标待核实/未说明。难度和准备建议可根据岗位名称、职责和一般经验作粗略预测，单独标注；不代表企业面试标准、个人资格或录用概率。

未知域不执行 Extract，摘要整理显示“详情待核实”，不会冒充完整 JD 或创建已核实 JobVersion。允许保存的正文沿用原抽取与证据链路。普通目录及无关页面折叠；明确异地、社招或过期信息降低相关性。城市包含区县时避免误判异地。

新增 `/search-runs/natural`、`/search-runs/{id}/organize`，候选接口附带最新 intelligence。迁移0010新增 search_candidate_analyses 版本表及 owner/候选/运行关联约束，保留原卷。来源策略收紧、导出和账号删除覆盖新表。详见 architecture.md、api.md。

搜索使用 advanced 公开摘要，模型每批处理3条，有结构/候选ID/事实原文校验、预算、一次修正、取消与租约保护。模型不能生成新链接；卡片只引用已有来源 URL。Prompt当前2026-10-23.6，明确允许在依据有限时预测难度。

## 实际验证

完整 `make verify`：106项后端测试、4项前端测试、5条浏览器流程，覆盖迁移/漂移、原业务、独立授权、事实过滤、隔离、来源撤回、预算、幂等整理、筛选/刷新/保存意向；类型/样式、构建与 OpenAPI 同步检查通过。见 verification-discovery.json/log。

真实验收使用隔离8082与公开招聘输入，无个人简历。用户原例实际检索22条去重来源；最终整理32条职位、19条推荐，19条均有粗略难度与准备建议，3条推荐含来源明确要求。其余明确要求缺失时留空，职责仍可展示。数量为该次外部响应，不是固定数量或已核实在招数。难度调整前记录 discovery-live-before-difficulty.json；最终重整见 discovery-live-evidence.json。全部找岗验收共27次LLM、7次Search，实际input/output tokens为65770/19639，Search报告14 credits；直接来源探针另列，不代表费用承诺。见 discovery-usage.json。Python/后端较窄搜索过滤后只有3条推荐，见 discovery-live-python-specific.json，不为凑数编造职位。

实习专门来源探针多数为历史/下线职位，保留 discovery-search-probe.json，未强制指定该站。搜索片段常缺完整要求或公司信息，需到原站核实；难度预测不补成招聘事实。没有完成全部职位当前有效性、全部正文可读性或模型准确率的验收。

真实卡片浏览器检查390/768/1440、无水平溢出与刷新恢复，见 discovery-browser-evidence.json、screenshots/*-discovery-live*.png。8081保留原账户与数据库，健康检查见 discovery-deploy-evidence.json。独立8082完成后关闭，验证卷保留供复查。
